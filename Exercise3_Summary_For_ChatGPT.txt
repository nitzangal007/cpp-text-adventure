CONTEXT FOR CHATGPT: C++ TEXT ADVENTURE GAME - EXERCISE 3 IMPLEMENTATION SUMMARY

This document describes all code changes made to implement Exercise 3 (Recording & 
Replay System) for a C++ console-based text adventure game. The implementation uses
OOP inheritance (Option A). Please analyze this to understand the full architecture.

===================================================================================
PART 1: PROJECT OVERVIEW
===================================================================================

The game is a 2-player console-based text adventure with:
- 3 screens (levels) loaded from .screen files
- Players move with WASD/IJKL keys
- Items: keys, bombs, torches, springs, switches
- Riddles that block progress until answered correctly
- A Room 3 boss with typing challenges
- Score tracking and lives system

EXERCISE 3 REQUIREMENT:
Add 4 runtime modes controlled by command-line flags:
1. Normal mode (no flags): Standard gameplay
2. Save mode (-save): Record all inputs and events to files
3. Load mode (-load): Visual replay from recorded files (non-blocking)
4. Silent mode (-load -silent): Headless verification, outputs PASS/FAIL

PART 2: NEW FILES CREATED

FILE: Steps.h / Steps.cpp
-------------------------
PURPOSE: Store and manage recorded player inputs with timing.

STRUCT StepEntry:
  - size_t iteration    // Game tick when key was pressed
  - int playerId        // 1 or 2
  - char key            // The key pressed

CLASS Steps:
  FIELDS:
  - unsigned long randomSeed_       // For determinism (Room3Boss RNG)
  - vector<string> screenFiles_     // Screen files used in recording
  - list<StepEntry> steps_          // Queue of recorded inputs

  METHODS:
  - static Steps loadFromFile(filename)  // Parse .steps file
  - bool saveToFile(filename)            // Write .steps file
  - void setRandomSeed(seed)             // Store RNG seed
  - unsigned long getRandomSeed()        // Retrieve for replay
  - void setScreenFiles(files)           // Store screen list
  - vector<string>& getScreenFiles()     // Get for replay
  - void addStep(iter, player, key)      // Record one input
  - bool hasMoreSteps()                  // Check if queue empty
  - bool isNextStepOnIteration(iter)     // Check timing match
  - StepEntry& peekStep()                // View without removing
  - StepEntry popStep()                  // Remove and return

FILE FORMAT (adv-world.steps):
  Line 1: <rng_seed>
  Line 2: <screen1.screen>,<screen2.screen>,...
  Remaining: <iteration> <playerId> <key>

FILE: Results.h / Results.cpp
-------------------------
PURPOSE: Store and manage observable game events for verification.

ENUM ResultType:
  - ScreenTransition = 0  // Player moved to another screen
  - LifeLost = 1          // Player died
  - RiddleEncounter = 2   // Riddle answered
  - GameFinished = 3      // Game completed

STRUCT ResultEntry:
  - size_t iteration
  - int playerId
  - ResultType type
  - int screenId          // For ScreenTransition
  - int riddleId          // For RiddleEncounter (unused currently)
  - bool riddleCorrect    // For RiddleEncounter
  - int finalScore        // For GameFinished

CLASS Results:
  FIELDS:
  - list<ResultEntry> results_

  METHODS:
  - static Results loadFromFile(filename)
  - bool saveToFile(filename)
  - void addScreenTransition(iter, player, toScreen)
  - void addLifeLost(iter, player)
  - void addRiddleEncounter(iter, player, riddleId, correct)
  - void addGameFinished(iter, score)
  - bool hasMoreResults()
  - ResultEntry popResult()
  - ResultEntry& peekResult()

FILE FORMAT (adv-world.result):
  Line 1: <count>
  Remaining: <iteration> <playerId> <type> [extra_data...]
  Type 0: extra = screenId
  Type 1: no extra
  Type 2: extra = riddleId, correct (0/1)
  Type 3: extra = finalScore

FILE: GameKeyboardInput.h / GameKeyboardInput.cpp
-------------------------
PURPOSE: Handle normal gameplay with optional recording (-save mode).
INHERITS FROM: Game

FIELDS:
  - bool saveEnabled_         // Whether to record
  - bool filesInitialized_    // Whether recording started
  - string stepsFilename_     // Output filename
  - Steps steps_              // Accumulated inputs
  - Results actualResults_    // Accumulated events

CONSTRUCTOR:
  GameKeyboardInput(bool saveEnabled)
  - Stores saveEnabled_ flag

DESTRUCTOR:
  ~GameKeyboardInput()
  - If saveEnabled_: calls saveFilesOnExit() to write files

OVERRIDDEN METHODS:
  void onInputReceived(iter, player, key):
    - If first input: initializeRecording() (capture seed, screen files)
    - Add step to steps_

  void onResultEvent(iter, player, type, data):
    - Add appropriate event to actualResults_

PRIVATE METHODS:
  void initializeRecording():
    - Capture Room3Boss RNG seed
    - Capture screen file list from Screens class

  void saveFilesOnExit():
    - Write steps_.saveToFile("adv-world.steps")
    - Write actualResults_.saveToFile("adv-world.result")

-------------------------
FILE: GameFileInput.h / GameFileInput.cpp
-------------------------
PURPOSE: Replay from files and optionally verify results (-load -silent).
INHERITS FROM: Game

FIELDS:
  - bool isSilent_           // true = verify mode
  - bool testPassed_         // Verification result
  - string failureMessage_   // Reason for failure
  - bool filesLoaded_        // Whether files loaded OK
  - Steps steps_             // Loaded inputs
  - Results expectedResults_ // Expected events (silent only)
  - Results actualResults_   // Actual events during replay

CONSTRUCTOR:
  GameFileInput(bool silent)
  - Sets isSilent_ and g_silentMode global
  - Calls loadFiles()

OVERRIDDEN METHODS:
  char getNextInput():
    - If steps queue has step with iteration <= currentIteration_:
      return popStep().key
    - Else return 0 (no input this frame)

  void onResultEvent(iter, player, type, data):
    - Add to actualResults_
    - If isSilent_: call verifyResult()

  bool shouldRender():
    - return !isSilent_

  bool shouldShowMenu():
    - return false (always skip menu)

  int getSleepDuration():
    - return isSilent_ ? 0 : 10

  bool isReplayComplete():
    - return !steps_.hasMoreSteps()

  bool shouldWaitForInput():
    - return false (never block on keyboard)

PUBLIC METHODS:
  bool didTestPass()
  string& getFailureMessage()
  void printTestResult():
    - Outputs "Test PASSED" or "Test FAILED: <reason>"
    - Also checks for missing events (expected > actual)

PRIVATE METHODS:
  bool loadFiles():
    - Check file existence with filesystem::exists
    - Load Steps from adv-world.steps
    - Set Room3Boss RNG seed for determinism
    - If silent: load Results from adv-world.result
    - Return false with failureMessage_ on any error

  void verifyResult(iter, player, type, data):
    - Pop expected result
    - Compare iteration, type, playerId
    - Compare extra data based on type (screenId, score, riddleCorrect)
    - Set testPassed_=false and failureMessage_ on mismatch

FILE: Game.cpp
--------------
CHANGES:
1. run(): Check shouldShowMenu() before showing menu
2. initGame(): Guard cls(), render() with shouldRender()
3. runGame(): 
   - Replace direct _kbhit()/_getch() with getNextInput()
   - Call onInputReceived() after processing input
   - Guard render() with shouldRender()
   - Check isReplayComplete() to exit loop
   - Use getSleepDuration() for Sleep()

4. handleRiddleEncounter():
   - Use shouldWaitForInput() to decide keyboard vs replay input
   - In replay: loop getNextInput() until answer found (with safety limit)
   - Call onResultEvent(type=2) for riddle outcome

5. tryAdvanceToNextScreen():
   - Call onResultEvent(type=0) for screen transitions
   - Guard _getch() with shouldWaitForInput()

6. decrementLife():
   - Call onResultEvent(type=1) for deaths
   - Call onResultEvent(type=3) for game over

7. showStoryOverlay(), showGameOverScreen():
   - Early exit if !shouldRender()
   - Replace _getch() with Sleep() if !shouldWaitForInput()

FILE: Main.cpp
--------------
MODIFIED to parse command-line arguments:

  bool isSave = false, isLoad = false, isSilent = false;
  for (int i = 1; i < argc; ++i) {
      string arg = argv[i];
      if (arg == "-save") isSave = true;
      if (arg == "-load") isLoad = true;
      if (arg == "-silent") isSilent = true;
  }

  unique_ptr<Game> game;
  GameFileInput* gameFile = nullptr;

  if (isLoad) {
      auto gf = make_unique<GameFileInput>(isSilent);
      gameFile = gf.get();
      game = move(gf);
  } else {
      game = make_unique<GameKeyboardInput>(isSave);
  }

  if (!isSilent) hideCursor();
  game->run();
  if (isSilent && gameFile) gameFile->printTestResult();

PART 4: RUNTIME FLOW DIAGRAM
===================================================================================

COMMAND LINE PARSING:
  .\game.exe           -> GameKeyboardInput(saveEnabled=false)
  .\game.exe -save     -> GameKeyboardInput(saveEnabled=true)
  .\game.exe -load     -> GameFileInput(silent=false)
  .\game.exe -load -silent -> GameFileInput(silent=true)

GAME LOOP (simplified):
  Game::run()
    |
    +-- shouldShowMenu()? --> false in replay, skip menu
    |
    +-- initGame()
    |     +-- Load screens (from steps file in replay)
    |     +-- shouldRender()? Draw initial state
    |
    +-- runGame()
          |
          while (running && !isReplayComplete()):
            ++currentIteration_
            ch = getNextInput()  // keyboard or file
            if (ch != 0):
              process input
              onInputReceived()  // record if saving
            updateLogic()        // collisions, events
              -> onResultEvent() on events
            if (shouldRender()): render()
            Sleep(getSleepDuration())
          |
          Game ends -> onResultEvent(type=3, score)

VERIFICATION (silent mode):
  Each onResultEvent():
    actual event vs expected from file
    -> mismatch sets testPassed_=false

  printTestResult():
    if testPassed_ and no leftover expected:
      "Test PASSED"
    else:
      "Test FAILED: <reason>"

PART 6: KEY DESIGN DECISIONS
===================================================================================

1. INHERITANCE OVER FLAGS:
   Instead of if/else chains checking mode flags, we use polymorphism.
   Game.cpp calls virtual methods; derived classes provide behavior.

2. TEMPLATE METHOD PATTERN:
   Game::run() is the template with fixed structure.
   Virtual hooks allow customization without changing flow.

3. GLOBAL SILENT FLAG (g_silentMode):
   Low-level functions (gotoxy, cls) can't access Game object.
   Global flag allows them to disable output in silent mode.

4. OVERDUE STEP HANDLING:
   getNextInput() returns steps with iteration <= current.
   This prevents desync if timing drifts during replay.

5. SAFETY LIMITS:
   Riddle input loop has MAX_SEARCH_ITERATIONS=10000.
   Prevents infinite loops if step data is corrupted.
