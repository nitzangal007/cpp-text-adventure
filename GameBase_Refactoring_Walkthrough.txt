1. STEPS CLASS (Steps.h / Steps.cpp)
--------------------------------------------------------------------------------

PURPOSE:
Records every key press (step) during gameplay with its exact game cycle
(iteration). This allows deterministic replay of the game.

DATA STRUCTURES:

    struct StepEntry {
        size_t iteration;   // Game cycle when the key was pressed
        int playerId;       // 1 or 2 (two-player game)
        char key;           // The key that was pressed (w,a,s,d,x,z,i,j,k,l,m,n)
    };

    class Steps {
        unsigned long randomSeed_;         // For Room3Boss RNG reproducibility
        std::vector<std::string> screenFiles_;  // Screen files used in game
        std::list<StepEntry> steps_;       // Recorded steps
    };

KEY METHODS:
- loadFromFile(filename)  - Load steps from .steps file for replay
- saveToFile(filename)    - Save recorded steps to file
- setRandomSeed(seed)     - Store RNG seed for boss room replay
- getRandomSeed()         - Retrieve stored RNG seed
- setScreenFiles(files)   - Store which screen files were used
- addStep(iteration, playerId, key) - Record a key press
- isNextStepOnIteration(iteration)  - Check if next step matches current cycle
- popStep()               - Get and remove next step for replay
- hasMoreSteps()          - Check if more steps remain

FILE FORMAT (adv-world.steps):
    <random_seed>
    <screen1.screen>,<screen2.screen>,<screen3.screen>
    <iteration> <player_id> <key>
    <iteration> <player_id> <key>
    ...

EXAMPLE:
    1126025823
    adv-world_01.screen,adv-world_02.screen,adv-world_03.screen
    14 1 d
    58 2 j
    68 1 a
    75 2 i

2. RESULTS CLASS (Results.h / Results.cpp)
--------------------------------------------------------------------------------

PURPOSE:
Records significant game events (results) for verification during replay.
In silent mode, actual results are compared against expected results.

DATA STRUCTURES:

    enum class ResultType {
        ScreenTransition = 0,  // Player moved to another screen
        LifeLost = 1,          // Player lost a life
        RiddleEncounter = 2,   // Player encountered a riddle
        GameFinished = 3       // Game completed
    };

    struct ResultEntry {
        size_t iteration;      // Game cycle when event occurred
        int playerId;          // 1 or 2 (0 for game-wide events)
        ResultType type;       // Type of event
        
        // Extra data depending on type:
        int screenId;          // For ScreenTransition: destination screen
        int riddleId;          // For RiddleEncounter: which riddle
        bool riddleCorrect;    // For RiddleEncounter: was answer correct
        int finalScore;        // For GameFinished: final score
    };

KEY METHODS:
- loadFromFile(filename)  - Load expected results for verification
- saveToFile(filename)    - Save recorded results to file
- addScreenTransition(iteration, playerId, toScreenId)
- addLifeLost(iteration, playerId)
- addRiddleEncounter(iteration, playerId, riddleId, correct)
- addGameFinished(iteration, finalScore)
- popResult()             - Get and remove next expected result
- hasMoreResults()        - Check if more expected results remain

FILE FORMAT (adv-world.result):
    <number_of_results>
    <iteration> <type> <player_id> [extra_data...]
    ...

--------------------------------------------------------------------------------
VIRTUAL HOOKS ADDED TO GAME CLASS
--------------------------------------------------------------------------------

1. getNextInput()
   - DEFAULT: Reads from keyboard using _kbhit() and _getch()
   - PURPOSE: Override in GameFileInput to read from file instead
   
2. onInputReceived(iteration, playerId, key)
   - DEFAULT: Empty (no-op)
   - PURPOSE: Override in GameKeyboardInput to record steps to file
   
3. onResultEvent(iteration, playerId, eventType, extraData)
   - DEFAULT: Empty (no-op)
   - PURPOSE: Override to record/verify result events
   - eventType values:
     * 0 = ScreenTransition (extraData = destination screen ID)
     * 1 = LifeLost (extraData unused)
     * 2 = RiddleEncounter (extraData encodes riddle info)
     * 3 = GameFinished (extraData = final score)

4. shouldRender()
   - DEFAULT: Returns true
   - PURPOSE: Override in GameFileInput to return false for silent mode
   
5. getSleepDuration()
   - DEFAULT: Returns 50ms (normal game speed)
   - PURPOSE: Override for faster replay (10ms) or instant (0ms)
   
6. shouldShowMenu()
   - DEFAULT: Returns true
   - PURPOSE: Override in GameFileInput to skip menu in load mode

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
1. GAMEKEYBOARDINPUT CLASS
--------------------------------------------------------------------------------

PURPOSE:
Handles normal gameplay and the -save mode. When saveEnabled_ is true,
it records all key presses and game events to files.

HEADER (GameKeyboardInput.h):

    class GameKeyboardInput : public Game {
        Steps steps_;
        Results results_;
        bool saveEnabled_ = false;
        bool filesInitialized_ = false;
        
    public:
        explicit GameKeyboardInput(bool saveToFiles = false);
        ~GameKeyboardInput() override;
        
    protected:
        void onInputReceived(size_t iteration, int playerId, char key) override;
        void onResultEvent(size_t iteration, int playerId, int eventType, int extraData) override;
        
    private:
        void initRecording();
        void saveFilesOnExit();
    };

BEHAVIOR:
- Constructor: Stores saveEnabled_ flag
- initRecording(): Captures screen files and RNG seed at game start
- onInputReceived(): Adds step to steps_ if recording
- onResultEvent(): Adds result to results_ if recording
- Destructor: Saves files when game exits (if recording was enabled)

USAGE:
    // Normal mode (no args)
    GameKeyboardInput game(false);  // saveEnabled = false
    game.run();
    
    // Save mode (-save)
    GameKeyboardInput game(true);   // saveEnabled = true
    game.run();
    // Files saved automatically on exit

--------------------------------------------------------------------------------
2. GAMEFILEINPUT CLASS
--------------------------------------------------------------------------------

PURPOSE:
Handles replay modes (-load and -load -silent). Reads input from files
instead of keyboard and optionally verifies results.

HEADER (GameFileInput.h):

    class GameFileInput : public Game {
        Steps steps_;
        Results expectedResults_;
        Results actualResults_;
        bool isSilent_ = false;
        bool testPassed_ = true;
        std::string failureMessage_;
        bool filesLoaded_ = false;
        
    public:
        explicit GameFileInput(bool silent = false);
        
    protected:
        char getNextInput() override;
        void onResultEvent(size_t iteration, int playerId, int eventType, int extraData) override;
        bool shouldShowMenu() const override { return false; }
        bool shouldRender() const override { return !isSilent_; }
        int getSleepDuration() const override;
        
    public:
        bool didTestPass() const { return testPassed_; }
        const std::string& getFailureMessage() const;
        void printTestResult() const;
        
    private:
        bool loadFiles();
        void verifyResult(size_t iteration, int playerId, int eventType, int extraData);
    };

BEHAVIOR:
- Constructor: Loads step and result files, sets RNG seed
- getNextInput(): Returns step from file (NOT from keyboard!)
- shouldShowMenu(): Returns false (skip menu)
- shouldRender(): Returns !isSilent_ (no rendering in silent mode)
- getSleepDuration(): Returns 0 if silent, 10 otherwise (fast replay)
- onResultEvent(): Verifies against expected results if silent
- printTestResult(): Outputs "Test PASSED" or "Test FAILED: <reason>"

USAGE:
    // Load mode (-load) - visual replay
    GameFileInput game(false);  // silent = false
    game.run();
    
    // Silent mode (-load -silent) - verification only
    GameFileInput game(true);   // silent = true
    game.run();
    game.printTestResult();

--------------------------------------------------------------------------------
KEY DESIGN DECISIONS
--------------------------------------------------------------------------------

1. POLYMORPHISM OVER CONDITIONALS:
   Instead of having if-else chains like:
       if (!isLoad) { read keyboard } else { read file }
   We use virtual methods that derived classes override.

2. TEMPLATE METHOD PATTERN:
   The base Game::runGame() method defines the algorithm skeleton.
   Derived classes customize specific steps via virtual hooks.

3. SINGLE RESPONSIBILITY:
   - Steps class: Only handles step recording/playback
   - Results class: Only handles result recording/verification
   - GameKeyboardInput: Only handles keyboard mode specifics
   - GameFileInput: Only handles file replay specifics

4. RNG SEED HANDLING:
   Room3Boss generates random math tasks. For replay to work:
   - Recording: Capture RNG seed before boss tasks are generated
   - Replay: Set RNG seed before entering boss room

GOAL:
Update Main.cpp to parse command-line arguments and instantiate the correct
Game subclass.

PLANNED CHANGES TO MAIN.CPP:

    int main(int argc, char** argv) {
        bool isLoad = hasArg(argc, argv, "-load");
        bool isSave = hasArg(argc, argv, "-save");
        bool isSilent = hasArg(argc, argv, "-silent");
        
        std::unique_ptr<Game> game;
        
        if (isLoad) {
            game = std::make_unique<GameFileInput>(isSilent);
        } else {
            game = std::make_unique<GameKeyboardInput>(isSave);
        }
        
        game->run();
        
        // Print test result in silent mode
        if (isLoad && isSilent) {
            static_cast<GameFileInput*>(game.get())->printTestResult();
        }
        
        return 0;
    }

COMMAND-LINE USAGE:

    cpp-texy-adventure.exe              # Normal mode (Exercise 2 behavior)
    cpp-texy-adventure.exe -save        # Normal + record to files
    cpp-texy-adventure.exe -load        # Replay from files (visual)
    cpp-texy-adventure.exe -load -silent # Replay for verification (no display)
